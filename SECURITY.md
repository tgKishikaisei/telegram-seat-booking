# Безопасность

## Как сообщить об уязвимости

Не открывайте публичный issue. Нажмите «Report a vulnerability» на вкладке **Security** или напишите мне в Telegram: [@BehruzAvezmatov](https://t.me/BehruzAvezmatov).

## Что сделано

- **Кто пришёл.** Каждый запрос к API мини-приложения несёт `initData` Telegram; сервер проверяет подпись (HMAC от токена бота) и срок жизни. Идентификатор пользователя берётся только из подписанных данных, не из тела запроса.
- **Двойная продажа.** Место занимается одним `UPDATE … WHERE` свободно или бронь истекла; если не хватило хотя бы одного места, откатывается вся бронь. Тест запускает трёх зрителей за одни и те же места на файловой базе.
- **Чужая бронь.** Бронь доступна по случайному идентификатору и только владельцу. Кто держит занятое место, API не раскрывает: для остальных оно просто «занято».
- **Сумма и счёт.** Цена считается по базе, из браузера приходят только ключи мест. Payload счёта подписан HMAC, `pre_checkout` сверяет плательщика, сумму и валюту. Повторное уведомление об оплате с тем же `charge_id` второй раз не засчитывается.
- **Деньги без мест.** На время оплаты бронь продлевается; если места всё же потеряны, звёзды возвращаются автоматически.
- **Билеты.** В QR — случайный код и HMAC. Отметка входа атомарная: второй раз тот же билет не пройдёт; проверять билеты могут только `STAFF_IDS` и `ADMIN_IDS`.
- **Ввод и вывод.** Схемы запросов с `extra="forbid"`, лимит размера тела, проверка заголовка Host. Мини-приложение строит разметку через `textContent`; CSP без inline-скриптов, встраивание разрешено только доменам Telegram.
- **Флуд.** Лимиты запросов и броней на пользователя в Redis.
- **Секреты.** В продакшене — Docker secrets (`secrets/<имя>` → `/run/secrets/<имя>`), не переменные окружения. `.env`, `secrets/` и данные исключены из git и из образа. Фильтр логов вырезает значения секретов и строки, похожие на токены.
- **Контейнеры.** Процесс без root, файловая система только для чтения, `cap_drop: ALL`, `no-new-privileges`; PostgreSQL и Redis — во внутренней сети без выхода наружу. У приложения отдельная роль БД без прав на изменение схемы.
- **Зависимости.** `requirements.lock` с SHA-256 каждого пакета и установка с `--require-hashes`; GitHub Actions закреплены по SHA коммита.

GitHub Actions на каждый push запускает тесты, проверку миграций, `bandit`, `pip-audit`, сборку образа, `trivy` (уязвимости, конфигурация, секреты) и `zizmor`.

## Что не проверялось

Нагрузочного тестирования и внешнего аудита не было. Оплата звёздами проверена тестами на подменённом Telegram, а не на боевых платежах.
